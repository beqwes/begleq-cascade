# begleq-cascade

Каскад нод: входная принимает клиентов и прозрачно перебрасывает трафик на выходную.
Проброс делает ядро через DNAT — TCP не терминируется, поэтому VLESS/Reality
проходит без искажений.

Debian/Ubuntu, запуск от root. Только IPv4.

```
Клиент → [вход :443] → DNAT → [выход :2053] → интернет
```

## Установка

```bash
wget -O /usr/local/bin/begleq-cascade https://raw.githubusercontent.com/beqwes/begleq-cascade/master/begleq-cascade.sh
chmod +x /usr/local/bin/begleq-cascade
```

Обновление — одной командой (или пункт `u` в меню):

```bash
begleq-cascade update
```

Скрипт берёт файл по SHA последнего коммита, а не по ветке, поэтому кэш
raw.githubusercontent не подсунет старую версию. Перед заменой проверяет,
что файл скачался целым, и обновляет копию для юнита автозагрузки.

## Быстрый старт

Одна команда поднимает вход целиком — ставит зависимости, тюнит систему,
создаёт правило и сохраняет его:

```bash
begleq-cascade add tcp 443 203.0.113.10 2053
```

Читается так: принимай TCP на `443` → отправляй на `203.0.113.10:2053`.

Клиентам отдаётся адрес входной ноды и входящий порт. Параметры протокола
(SNI, ключи, flow) остаются от выходной ноды и не меняются.

## Команды

| Команда | Описание |
|---|---|
| `begleq-cascade` | интерактивное меню |
| `add tcp ПОРТ IP ПОРТ [имя]` | маршрут для VLESS / XRay / Trojan |
| `add udp ПОРТ IP ПОРТ [имя]` | маршрут для WireGuard / Amnezia / Hysteria |
| `list` | активные маршруты |
| `del tcp ПОРТ` | удалить маршрут |
| `replace-hop СТАРЫЙ_IP НОВЫЙ_IP` | сменить выход, не трогая порты |
| `doctor [IP ПОРТ]` | диагностика |
| `except add tcp ПОРТ IP` | не пересылать подключения с IP на этом маршруте (см. ниже) |
| `except add IP` | не пересылать подключения с IP ни на одном маршруте |
| `except del …` | снять исключение (те же аргументы) |
| `update` | обновить скрипт с GitHub |
| `sync` | поднять маршруты из базы (то же делается при загрузке) |
| `tune` | применить тюнинг системы отдельно |
| `tune --exit` | то же + настройки для выходной ноды (см. ниже) |

Примеры:

```bash
begleq-cascade add udp 51820 203.0.113.10 51820 wg
begleq-cascade replace-hop 203.0.113.10 203.0.113.20
begleq-cascade doctor 203.0.113.10 2053
```

## Проверка

`doctor` показывает форвардинг, заполненность conntrack, маршруты,
включено ли автовосстановление после ребута и прогоняет TCP-пробы до выхода.

Две вещи, о которых легко забыть:

- **Проверять только с внешнего хоста.** DNAT срабатывает в цепочке `PREROUTING`,
  то есть ловит лишь входящий трафик. Запрос с самой ноды идёт через `OUTPUT`,
  правило не сработает — получишь ложное «не работает».
- **Пинг ничего не доказывает.** ICMP часто проходит там, где TCP уже режется.
  Верить только TCP-пробе.

## Маскировочный сайт на входной ноде

DNAT не видит SNI и пересылает на выход всё, что пришло на порт, — в том числе
браузеры и проверяющих. Чтобы по адресу входной ноды открывался её сайт,
Reality на выходе указывает `target` на домен входной ноды:

```
браузер → вход :443 → DNAT → выход (Reality: «не мой клиент») → target = домен входа :443
```

Запрос Reality за сайтом снова приходит на вход и без исключения ушёл бы по
DNAT обратно на выход — петля, сайт не открывается. Исключение пропускает
подключения с IP выхода мимо DNAT в локальный nginx:

```bash
begleq-cascade except add tcp 443 203.0.113.10
```

Исключение можно поставить и сразу на все маршруты — по одному IP:

```bash
begleq-cascade except add 203.0.113.10
```

Оно разворачивается в правило на порт каждого маршрута и само распространяется
на маршруты, добавленные позже. Общий `-s IP -j RETURN` скрипт не ставит:
он увёл бы этот IP и мимо `-j DOCKER`, и у него сломались бы опубликованные
порты контейнеров. Ручное такое правило скрипт берёт под управление и заменяет.

Исключения хранятся в `/etc/begleq-cascade/except.db` и поднимаются при загрузке
вместе с маршрутами, всегда выше DNAT. Ручное правило вида
`-s IP -p tcp --dport 443 -j RETURN` для порта существующего маршрута скрипт
при запуске берёт под управление сам. `doctor` предупреждает, если на порту
маршрута слушает локальный сервис, а выход не исключён.

Nginx на входе должен принимать на `:443` обычный TLS без `proxy_protocol`,
а в Reality на выходе — `xver: 0`.

## Что делает автоматически

- Ставит `iptables` и `conntrack`, если их нет.
- Включает `ip_forward` через `/etc/sysctl.d`, поднимает `nf_conntrack_max`
  (по объёму RAM: 512 МБ → 131 072, 2 ГБ → ~420 000, от ~5 ГБ — 1 048 576) и срезает таймаут
  established — дефолтные 65 536 и 5 суток переполняют таблицу на релее.
- Прописывает `nf_conntrack` и `tcp_bbr` в автозагрузку модулей, иначе параметры
  conntrack после ребута не применятся.
- Если у сетевой карты одна очередь приёма (типично для VPS), включает RPS/RFS:
  разбор пакетов идёт на всех ядрах, а не на одном. Пересылка DNAT целиком
  живёт в softirq, и без этого под нагрузкой одно ядро упирается в 100%,
  пока остальные простаивают.
- Ставит qdisc `fq` на сетевые карты: `default_qdisc=fq` действует только на
  интерфейсы, поднятые позже, и уже работающая карта остаётся на `fq_codel`.
  RPS и `fq` восстанавливает при загрузке `begleq-net.service`; `doctor`
  предупреждает, если одно из них не на месте.
- Для каждого маршрута ставит DNAT, MASQUERADE только для трафика к выходу
  (через интерфейс, куда реально идёт маршрут) и разрешающие правила `FORWARD`
  в обе стороны — работает и при `policy DROP` от docker или ufw.
- Сбрасывает conntrack при смене выхода, убирает ставшие ненужными правила
  и предупреждает, если входящий порт (TCP или UDP) уже занят.

Все правила помечены комментарием `begleq-cascade`. Команды трогают только
помеченные правила; чужие DNAT видны в `list` отдельной строкой.

## Выходная нода: `tune --exit`

Reality на каждое подключение клиента — и своего тоже — сама соединяется
с `target`, чтобы скопировать ответ настоящего сайта. Если `target` на другом
сервере (например, на входе каскада), выход открывает сотни соединений
в секунду на один `ip:443` и сам их закрывает. TIME-WAIT копятся к одному
адресу, и каждый `connect()` перебирает почти забитый диапазон исходящих портов
под блокировкой ядра: до ~20% CPU в `sys` и риск исчерпать порты в пик.

```bash
begleq-cascade tune --exit
```

Ставит `tcp_tw_reuse=1` (безопасно при `tcp_timestamps`, меняет только
исходящие) и диапазон портов `10000–65535`, а слушающие порты служб ≥10000
резервирует, чтобы ядро не отдало их исходящим соединениям. Пишется в
`/etc/sysctl.d/99-zz-begleq-exit.conf`. `doctor` замечает тысячи TIME-WAIT
к одному адресу без этих настроек и подсказывает команду.

## Переживание ребута

Маршруты хранятся в `/etc/begleq-cascade/routes.db`. При загрузке юнит
`begleq-cascade.service` запускает `begleq-cascade sync`: ставит недостающие
правила и снимает помеченные, которых в базе нет. Для юнита скрипт кладёт
свою копию в `/usr/local/lib/begleq-cascade/` и обновляет её при каждом изменении.

`iptables-persistent` не нужен и не ставится: он конфликтует с ufw, а
`netfilter-persistent save` на хосте с docker сохраняет динамические правила
docker, и после ребута они задваиваются. Если `netfilter-persistent` уже
установлен и docker нет, скрипт по-прежнему обновляет `rules.v4`.

## Обновление с 1.0

Ничего делать не нужно: при первом запуске новая версия находит свои старые
правила по `routes.db` и помечает их. Общее правило
`-o eth0 -j MASQUERADE`, которое ставила 1.0, остаётся — оно могло
понадобиться другим сервисам. `doctor` подскажет, как его снять.

## Файлы

| Путь | Назначение |
|---|---|
| `/etc/begleq-cascade/routes.db` | маршруты — источник истины для `sync` |
| `/etc/begleq-cascade/except.db` | исключения из пересылки |
| `/etc/systemd/system/begleq-cascade.service` | восстановление маршрутов при загрузке |
| `/usr/local/lib/begleq-cascade/begleq-cascade` | копия скрипта для юнита |
| `/etc/sysctl.d/99-begleq-cascade.conf` | conntrack, forwarding, BBR |
| `/etc/modules-load.d/begleq-cascade.conf` | загрузка `nf_conntrack`, `tcp_bbr` при старте |
| `/etc/modprobe.d/begleq-cascade.conf` | `hashsize` для conntrack |
| `/etc/systemd/system/begleq-net.service` | RPS/RFS и qdisc `fq` при загрузке |
| `/etc/sysctl.d/99-zz-begleq-exit.conf` | настройки выходной ноды (`tune --exit`) |
